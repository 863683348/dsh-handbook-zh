# 05 · 工具开发进阶：schema、文件系统、提示词与生命周期

> 一句话总结：生产级插件 = 严谨的 JSON Schema（参数与输出）+ 安全的 \`ctx.fs\` 文件访问（含工作区 containment 校验）+ 恰到好处的提示词段落 + 可清理的生命周期管理；本章用真实插件 \`dsh-plugin-focus\` 的写法讲透这四件事，并给出多工具插件的组织方式。

## 1. defineTool 全字段

从 [04-写第一个插件](04-写第一个插件.md) 我们知道工具通过 \`ctx.tools.register(defineTool({...}))\` 注册。\`defineTool\` 的核心字段：

| 字段 | 类型 | 作用 |
| --- | --- | --- |
| \`name\` | string | 工具名，模型调用时用；**避免与内置工具冲突**（\`read\`/\`write\`/\`edit\`/\`glob\`/\`grep\`/\`pwsh\`/\`todo_write\` 等） |
| \`description\` | string | 给模型看的说明：何时用、怎么用、有什么副作用 |
| \`parameters\` | object | 参数 schema（JSON Schema 风格的扁平字段描述） |
| \`output.schema\` | JSON Schema | 返回值的规范 schema（\`type: "object"\` + \`properties\`） |
| \`output.render\` | fn | 把规范值渲染成界面文本：\`(_args, value) => [{ type: "text", text }]\` |
| \`execute(args, exec)\` | async fn | 工具实现，返回**规范值**（必须符合 output.schema） |
| \`presentCall\` | fn | 调用记录在 UI 上的展示卡片 |

## 2. parameters：扁平字段式 JSON Schema

DSH 模型的工具参数用 JSON Schema 描述。官方插件（如 focus、recipe、gov）的写法是**扁平字段式**：每个字段一个键，值是该字段的约束：

\`\`\`js
parameters: {
  action: {
    type: "string",
    required: true,
    enum: ["set", "get", "append", "clear"],
    description: "对专注板做什么操作。",
  },
  note: {
    type: "string",
    description: "笔记内容；set / append 必填，get / clear 忽略。",
  },
}
\`\`\`

常用约束键：

| 键 | 说明 | 例子 |
| --- | --- | --- |
| \`type\` | 字段类型 | \`"string"\`、\`"integer"\`、\`"boolean"\`、\`"array"\` |
| \`required\` | 是否必填 | \`true\`（必填） |
| \`enum\` | 枚举取值 | \`["set", "get", "append", "clear"]\` |
| \`description\` | 给模型的字段说明 | 写清楚何时必填、何时忽略 |
| \`items\` | 数组元素类型 | \`items: { type: "string" }\` |

> 经验：字段越少、枚举越明确，模型调用越稳定。把"动作"收敛成 \`enum\` 是最常见的模式（focus 的 \`action\`、recipe 的 \`action\`、gov 的 \`action\` 都是如此）。

## 3. output.schema + render：让返回值"规范且好看"

工具返回的必须是**规范值**（canonical value）——即符合 \`output.schema\` 的对象，而不是自由文本。规范值的好处：后续环节（审计、UI、其他工具）可以结构化地消费它。

\`\`\`js
output: {
  schema: {
    type: "object",
    additionalProperties: false,
    required: true,
    properties: {
      action: { type: "string", required: true },
      path: { type: "string", required: true },
      entries: { type: "integer", required: true },
      changed: { type: "boolean", required: true },
      board: { type: "string" },
    },
  },
  render: (_args, value) => {
    const head = "Focus " + value.action + ": " + value.entries + " 条, " + (value.changed ? "已变更" : "未变更") + " — " + value.path;
    const lines = [head];
    if (value.board !== undefined) lines.push("", value.board);
    return [{ type: "text", text: lines.join("\n") }];
  },
}
\`\`\`

- \`additionalProperties: false\`：返回值里不允许 schema 之外的字段，强制规范；
- \`render\` 接收 \`(_args, value)\`，返回消息块数组（如 \`[{ type: "text", text }]\`），决定模型/用户看到什么文本；
- 结构数据（schema 里的字段）与展示文本（render 的输出）分离，是 DSH 工具的最佳实践。

## 4. execute 与 exec 上下文

\`execute(args, exec)\` 里能拿到什么？看官方插件 focus 的实际用法：

\`\`\`js
execute: async (args, exec) => {
  const cwd = exec.agent?.session?.header?.cwd; // 会话工作区！
  const signal = exec.signal;                   // 取消信号
  // ... 用 cwd 定位文件，返回规范值
  return { action, path, entries, changed, archived };
}
\`\`\`

要点：

- **\`exec.agent.session.header.cwd\` 是会话工作区**——"文件放哪"都以它为基准，绝不要写死绝对路径；
- \`exec.signal\`：调用被取消时置为 aborted，长任务要响应它；
- 抛 \`Error\` 即工具失败，模型会看到错误信息（错误消息要写人话）；
- 返回对象必须匹配 \`output.schema\`。

## 5. ctx.fs：文件读写与工作区 containment

**插件读写文件必须走宿主 \`ctx.fs\` 服务**，不要直接 \`fs\`。常用方法（以 focus 源码为证）：

| 方法 | 作用 |
| --- | --- |
| \`ctx.fs.resolve(path, { cwd, signal })\` | 相对 \`cwd\` 解析出目标 |
| \`ctx.fs.contains(target, other)\` | 判断 \`other\` 是否在 \`target\` 之内（containment 校验） |
| \`ctx.fs.stat(target, signal)\` | 取文件信息；不存在返回 \`undefined\` |
| \`ctx.fs.readText(target, signal)\` | 读文本 |
| \`ctx.fs.writeText(target, content, undefined, signal)\` | 写文本（第三参为可选的编码/选项） |
| \`ctx.fs.processPath(target)\` | 把目标转成展示用路径 |

**工作区 containment 是安全底线**：插件配置里出现的路径（如专注板文件）必须是"相对会话工作区的路径"，并且**永远不能逃逸工作区**。官方插件的标准写法是"解析后校验"：

\`\`\`js
async function resolveTarget(ctx, file, cwd, signal) {
  // 1) 先解析：相对 cwd 的文件路径 → 绝对目标
  const target = await ctx.fs.resolve(file, cwd !== undefined ? { cwd, signal } : { signal });
  if (cwd !== undefined) {
    // 2) 再校验：目标必须在工作区之内，否则直接拒绝
    const cwdTarget = await ctx.fs.resolve(".", { cwd, signal });
    if (!ctx.fs.contains(cwdTarget, target)) {
      throw new Error('configured file "' + file + '" escapes the session workspace');
    }
  }
  return target;
}
\`\`\`

> 为什么这么重要？插件运行在 Agent 进程里，若允许任意路径，一个被诱导的插件配置就能让 Agent 读写工作区之外的文件。**所有**解析出的路径都要过 \`ctx.fs.contains\` 这道闸。dsh-plugin-focus 里板子文件配置成工作区外路径会"fail loud"（直接报错），这是刻意设计。

## 6. ctx.systemPrompt.section：注入提示词

教模型"什么时候用什么工具、别干什么"，靠提示词段落。注册方式：

\`\`\`js
ctx.effect(() => ctx.systemPrompt.section({
  name: "focus:instructions",   // 段落名
  order: 5,                     // 顺序（persona 为 0，升序排列）
  text: "The focus tool maintains a durable focus board...",
}), "focus.section()");
\`\`\`

- \`order\` 控制段落先后（如 persona 是 0，插件段落常用 5）；
- 段落文本面向模型，写"何时用、怎么用、注意事项"；
- 用 \`ctx.effect\` 包裹：插件卸载时段落自动移除，不留垃圾。

## 7. ctx.effect 与事件钩子：生命周期管理

\`ctx.effect(fn, label)\` 是 Cordis 的生命周期原语：\`fn\` 里注册的一切（监听器、段落、定时器）在插件作用域结束时自动清理。注册事件钩子的标准姿势：

\`\`\`js
// 工具执行前拦截（dsh-gov 的策略门禁）
ctx.on("tools/pre-execute", async (exec, next) => {
  // 返回 { kind: "deny" | "ask", reason } 直接裁决；否则放行 next()
  return next();
});

// 工具执行后观察结果（dsh-gov 的审计）
ctx.on("tools/result", (exec, result) => {
  // result.isError 标记成败
});

// 每轮 Agent 步进前（dsh-gov 的配额计量、dsh-plugin-focus 的板子注入）
ctx.on("agent/pre-step", async ({ agent, turn, step, signal }, next) => {
  const decision = await next();
  if (decision.kind === "reject") return decision;
  // 可以往模型上下文里追加 plugin snapshot 消息
  return decision;
});
\`\`\`

\`inject\` 数组声明依赖（\`["tools", "fs", "systemPrompt", "agents", "tokenMeter"]\`），宿主保证这些服务就绪后才 \`apply\`。以官方包为参考：\`dsh-gov\` 就 \`inject\` 了 \`tokenMeter\` 来做 token 配额。可用服务清单以官方文档为准。

## 8. 多工具插件：一个插件注册多个工具

一个插件可以注册任意多个工具（以及多个段落、多个钩子）。组织方式：

\`\`\`js
function apply(ctx, config) {
  ctx.tools.register(defineTool({ name: "tool_a", /* ... */ }));
  ctx.tools.register(defineTool({ name: "tool_b", /* ... */ }));

  ctx.effect(() => ctx.systemPrompt.section({ /* section 1 */ }), "plugin.section1()");
  ctx.effect(() => ctx.systemPrompt.section({ /* section 2 */ }), "plugin.section2()");
  // 所有注册都在 apply 里完成，Cordis scope 统一清理
}
\`\`\`

dsh-gov 就是多工具插件：一个 \`gov\` 工具 + \`tools/pre-execute\`、\`tools/result\`、\`agent/pre-step\` 三个钩子 + 提示词段落。工具多时建议把每个工具的 schema 提取成常量，保持 \`apply\` 可读。

## 9. 进阶最佳实践清单

- [ ] \`parameters\` 用扁平 JSON Schema，动作收敛为 \`enum\`，字段写清"何时必填"
- [ ] 返回值是规范值（\`output.schema\` 约束），\`render\` 负责展示
- [ ] 用 \`exec.agent.session.header.cwd\` 定位工作区，不写死绝对路径
- [ ] 文件读写走 \`ctx.fs\`，且解析后过 \`ctx.fs.contains\` containment 校验
- [ ] 提示词段落用 \`ctx.effect\` 包裹，设置 \`order\`
- [ ] 事件钩子返回规范决策（\`next()\` / \`{kind: "deny"}\`），长任务响应 \`signal\`
- [ ] 纯逻辑（无 DSH/Cordis 依赖）抽到独立模块，便于单测——见下一章案例
