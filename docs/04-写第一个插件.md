# 04 · 写第一个插件：三件套骨架与 hello 工具

> 一句话总结：一个可安装的 DSH 插件只有三个文件——\`package.json\`（声明"我是组合包"）、\`cordis.patch.yml\`（把自己插入组合树）、\`lib/index.js\`（Cordis 插件本体），本章逐个文件拆解并写一个最小可运行的 \`hello\` 插件，装进本地 profile 验证。

## 1. 三件套总览

| 文件 | 内容 | 一句话职责 |
| --- | --- | --- |
| \`package.json\` | \`dsh.bundle.patch\` 指向 \`cordis.patch.yml\` + peerDependencies + \`publishConfig.access: public\` | 声明"这是一个 DSH 插件组合包" |
| \`cordis.patch.yml\` | \`insert\` 组合补丁 | 把自己（一行组合行）插进组合树 |
| \`lib/index.js\` | Cordis 插件：导出 \`{ name, inject, Config, apply }\` | 实际注册工具、注入提示词、管理生命周期 |

目录结构：

\`\`\`text
hello-plugin/
├── package.json
├── cordis.patch.yml
└── lib/
    └── index.js
\`\`\`

下面我们把 \`hello-plugin\` 写出来：它注册一个 \`hello\` 工具，向模型提供"打招呼 + 汇报当前工作区"的能力。

## 2. package.json：插件的身份声明

\`\`\`json
{
  "name": "hello-plugin",
  "version": "0.1.0",
  "description": "第一个 DSH 插件：注册一个 hello 工具",
  "type": "module",
  "main": "lib/index.js",
  "files": ["lib", "cordis.patch.yml", "README.md"],
  "license": "MIT",
  "publishConfig": { "access": "public" },
  "dsh": { "bundle": { "patch": "./cordis.patch.yml" } },
  "peerDependencies": {
    "@deepseek-ai/cordis": "^4.0.1",
    "@deepseek-ai/dsh-fs": "^0.1.0-rc.6",
    "@deepseek-ai/dsh-system-prompt": "^0.1.0-rc.6",
    "@deepseek-ai/dsh-tools": "^0.1.0-rc.6",
    "@deepseek-ai/schemastery": "^3.18.1"
  }
}
\`\`\`

逐字段要点：

| 字段 | 说明 |
| --- | --- |
| \`type: "module"\` | 插件用 ESM 编写（与 DSH 一致） |
| \`main\` | 指向 Cordis 插件入口 \`lib/index.js\` |
| \`files\` | 发布进 npm 包的文件白名单 |
| \`dsh.bundle.patch\` | **核心**：告诉 DSH"我的组合补丁是 ./cordis.patch.yml"，有此声明才被识别为插件组合包 |
| \`publishConfig.access: public\` | 发布到 npm 时公开访问（发布章节细讲） |
| \`peerDependencies\` | 官方 \`@deepseek-ai/*\` 运行时一律放 peerDependencies，由宿主提供，插件不重复安装 |

> 为什么官方包用 peerDependencies？因为 DSH 宿主（profile 运行时）已经装载了 \`dsh-tools\`、\`dsh-fs\` 等，插件直接复用同一份，避免版本分裂。**这个习惯不要破坏。**

## 3. cordis.patch.yml：把自己插进组合树

\`\`\`yaml
# Bundle patch layer：launcher 组合从空列表开始，所以这里的补丁都是 insert
- insert:
    - id: hello
      name: 'hello-plugin'
      config:
        greeting: '你好，我是第一个 DSH 插件！'
\`\`\`

- \`insert\`：往组合列表里**追加一行组合行**。回忆 02 章，profile 的配置树从空根开始叠加 patch，因此这里用 \`insert\` 而不是修改既有行；
- \`id\`：组合行唯一标识（如 \`hello\`），也是插件的 Cordis 名字；
- \`name\`：包名（\`'hello-plugin'\`），运行时从这里解析插件实现；
- \`config\`：传给插件 \`Config\` 的配置对象（可省略，用默认值）。

## 4. lib/index.js：Cordis 插件本体

\`\`\`js
// hello-plugin/lib/index.js
import z from "@deepseek-ai/schemastery";
import { defineTool } from "@deepseek-ai/dsh-tools";

/** Cordis 插件名（与组合行 id 一致）。 */
const name = "hello";

/** 本插件依赖的宿主服务，全部就绪后才会 apply。 */
const inject = ["tools", "systemPrompt"];

/** 组合行 config 的校验/默认值 schema。 */
const Config = z.object({
  greeting: z.string().default("你好，我是第一个 DSH 插件！"),
});

function apply(ctx, config) {
  // 1) 注册模型工具
  ctx.tools.register(defineTool({
    name: "hello",
    description: "向用户打招呼，并汇报当前会话的工作区路径。",
    parameters: {
      name: { type: "string", required: true, description: "要打招呼的对象名字。" },
    },
    output: {
      schema: {
        type: "object",
        additionalProperties: false,
        required: true,
        properties: {
          message: { type: "string", required: true },
        },
      },
      render: (_args, value) => [{ type: "text", text: value.message }],
    },
    execute: async (args, exec) => {
      const cwd = exec.agent?.session?.header?.cwd; // 会话工作区
      return { message: config.greeting + " " + args.name + "（工作区：" + (cwd ?? "未知") + "）" };
    },
    presentCall: (args) => ({ card: "generic", title: "Hello " + args.name, kind: "other", rawInput: args }),
  }));

  // 2) 注入一段提示词，教模型什么时候用 hello
  ctx.effect(() => ctx.systemPrompt.section({
    name: "hello:instructions",
    order: 5,
    text: "当用户想测试插件是否工作时，调用 hello 工具。",
  }), "hello.section()");
}

export { Config, apply, inject, name };
\`\`\`

结构拆解：

| 导出 | 作用 |
| --- | --- |
| \`name\` | 插件名字符串，加载器用它注册（须与组合行 \`id\` 一致） |
| \`inject\` | 依赖的宿主服务数组（\`tools\`、\`systemPrompt\`、\`fs\`、\`agents\` 等），全部就绪才 apply |
| \`Config\` | 用 schemastery（\`z.object\`）描述配置 schema，缺省值在这里给 |
| \`apply(ctx, config)\` | 插件主体：\`ctx.tools.register(defineTool(...))\` 注册工具；\`ctx.effect(...)\` 管理生命周期 |

\`defineTool\` 的关键字段（下一章细讲）：\`name\`、\`description\`、\`parameters\`（JSON Schema）、\`output.schema\` + \`output.render\`、\`execute(args, exec)\`（返回规范值）、\`presentCall\`（界面展示）。

## 5. 安装到本地 profile 并验证

### 5.1 语法自检（发布前随时可做）

\`\`\`powershell
node --check lib\index.js
\`\`\`

\`\`\`bash
node --check lib/index.js
\`\`\`

> 沙箱/CI 环境里 \`node --test\` 可能因为子进程被拦截而报 EPERM，此时改用"主模块方式"直接跑测试文件，详见 [08-常见问题](08-常见问题.md)。

### 5.2 装进 profile

用本地路径安装（开发期标准姿势，等价于 \`pnpm add <路径>\` + 自动 reconcile bundles 列表）：

\`\`\`powershell
# PowerShell（Windows 路径用反斜杠）
dsh plugin --profile dev add D:\dev\hello-plugin
\`\`\`

\`\`\`bash
# bash
dsh plugin --profile dev add ~/dev/hello-plugin
\`\`\`

### 5.3 验证三步走

**① 组合树里有没有它：**

\`\`\`powershell
dsh --profile dev --dump-config | Select-String -Pattern "hello"
\`\`\`

\`\`\`bash
dsh --profile dev --dump-config | grep hello
\`\`\`

**② 重启后跑一次会话，让模型调用工具：**

\`\`\`powershell
dsh --profile dev "调用 hello 工具，向'新同学'打个招呼"
\`\`\`

\`\`\`bash
dsh --profile dev "调用 hello 工具，向'新同学'打个招呼"
\`\`\`

**③ 看结果：** 模型应返回形如 \`你好，我是第一个 DSH 插件！ 新同学（工作区：...）\` 的消息，且工作区路径与运行命令的目录一致——工具真的跑起来了。

### 5.4 调配置试试

改 \`cordis.patch.yml\` 里的 \`greeting\`，重启后再问一次，问候语会跟着变。这验证了 \`config\` → \`Config\` → 工具行为的完整链路。

## 6. 新手插件检查清单

- [ ] \`package.json\` 含 \`dsh.bundle.patch\` 与 \`publishConfig.access: public\`
- [ ] 官方 \`@deepseek-ai/*\` 全部在 peerDependencies
- [ ] \`cordis.patch.yml\` 用 \`insert\` 追加组合行，\`id\` 与插件 \`name\` 一致
- [ ] \`lib/index.js\` 导出 \`{ name, inject, Config, apply }\`
- [ ] \`node --check\` 通过；\`dsh plugin add <路径>\` 成功
- [ ] \`--dump-config\` 能看到组合行；会话里模型能调用 \`hello\`
