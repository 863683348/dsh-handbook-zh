# 07 · 实战案例：拆解 3 个真实插件的设计

> 一句话总结：从 863683348 插件家族里挑三个代表——\`dsh-plugin-focus\`（专注板）、\`dsh-recipe\`（场景配方）、\`dsh-gov\`（治理套件）——看它们如何把前几章的原则落进代码：三件套结构、纯逻辑分层、schema 先行、ctx.fs 安全、生命周期管理与 fail-safe。

## 1. 三个插件一览

| 插件 | 一句话定位 | 核心工具 | 状态 |
| --- | --- | --- | --- |
| \`dsh-plugin-focus\` | 给 Agent 一块跨压缩、跨会话存活的"专注板" | \`focus\`（set/get/append/clear） | ✅ 稳定 + 🧪 实验面板 |
| \`dsh-recipe\` | "插件界的 dotfiles"：把插件打包成场景配方 | \`recipe\`（list/search/apply/compose） | ✅ 稳定 |
| \`dsh-gov\` | 企业配套：权限门禁 + 审计日志 + token 配额 | \`gov\`（status/policy/audit/quota） | ✅ 稳定 |

三者都已在 npm 发布、仓库打了 \`dsh-plugin\` topic、进入 awesome 生态，正好是第 06 章流程的活标本。下面逐个拆解。

## 2. dsh-plugin-focus：持久化专注板

**解决什么问题：** todo 列表管"下一步做什么"，专注板管"为什么做、什么不能漂移"——目标、硬约束、已做决定。这些信息在上下文压缩（compaction）后会丢，focus 把它们持久化到工作区文件里。

**核心设计（来自 README 与源码）：**

- **板子是一个纯文本文件**：默认 \`.dsh/focus.md\`，位于会话工作区；条目带时间戳按序排列，\`get\` 最新在前、按 \`maxChars\`（默认 8000）截断视图但**永不删文件内容**；
- **\`focus\` 工具四个动作**：

| action | 参数 | 行为 |
| --- | --- | --- |
| \`set\` | \`note\`（必填） | 追加一条"当前焦点/约束" |
| \`append\` | \`note\`（必填） | 追加日志条目（决定、发现、反转） |
| \`get\` | — | 读整块板（最新在前、截断并注明省略数） |
| \`clear\` | — | 清空；旧板归档到 \`.dsh/focus.md.bak\`（累积） |

- **自动注入**：复刻内置 \`dsh-time-context\` 机制——\`agent/pre-step\` waterfall 监听器在每轮开始（step 1）以及板子变化时，把板子作为 plugin snapshot 消息追加回模型上下文。会话恢复后第一步就能把板子带回来；
- **\`focusBoard\` 会话投影**：每次写入触发 \`focus/write\` 事件，UI 可用 \`useProjection('focusBoard')\` 读取；Web 面板（🧪 实验性）经包的 \`dsh.client\` manifest 在同一组合行上加载 \`./client\`；
- **安全**：所有文件访问走 \`ctx.fs\`，每个路径解析后都做工作区 containment 校验（\`ctx.fs.contains\`），板子**永远逃不出工作区**；
- **纯逻辑分层**：\`lib/board.js\` 零 DSH/Cordis 依赖（解析/渲染/变更/归档），独立单测；\`lib/index.js\` 只做接线。

**配置（组合行 config，全部可选）：** \`file\`（默认 \`.dsh/focus.md\`）、\`archiveFile\`、\`archive\`、\`maxEntries\`（60）、\`maxChars\`（8000）、\`autoInject\`（true）、\`personaSection\`（true）、\`sectionOrder\`（5）。

**值得学的点：** 板子按"工作区"而非"会话"存放——同一 workspace 的新会话能续上旧板子；视图截断不删数据；归档让"清空"可追溯。

## 3. dsh-recipe：场景配方（插件界的 dotfiles）

**解决什么问题：** 用户要的是**环境**（"浏览器开发环境"、"学术写作套装"、"通知全家桶"），不是一个一个插件。recipe 把"装一套环境"做成一次对话。

**核心设计：**

- **\`recipe\` 工具四个动作**：

| action | 参数 | 行为 |
| --- | --- | --- |
| \`list\` | — | 浏览全部配方 |
| \`search\` | \`need\` | 按自然语言需求匹配配方 |
| \`apply\` | \`recipeId\` 或 \`need\` | 展开配方：有序插件清单 + 安装命令序列 |
| \`compose\` | \`recipeId\`（逗号分隔） | 合并多个配方为整套环境（去重、保序） |

- **内置 10 个配方**：浏览器开发环境（4 插件）、通知全家桶（6）、学术写作套装（5）、移动远程控制（3）、安全加固套装（4）、记忆持久化套装（5）、娱乐休闲（4）、模型路由优化（5）、工作流自动化（5）、插件市场管理（5）；
- **配方格式即数据**：\`{ id, name, nameZh, description, descriptionZh, tags, plugins: [{ name, config? }] }\`——依赖顺序就是数组顺序；\`compose\` 做并集去重，天然为 DAG 化编排留了前置；
- **纯逻辑 + 数据分离**：\`lib/recipe.js\`（检索/展开/组合/命令序列）零依赖；\`lib/recipe-data.json\`（配方）+ \`lib/plugins.json\`（84 个插件目录，与 dsh-need-finder 同源）；
- **安全声明**：无网络、无写入、无 secrets——它只"算"，不"动"；
- 输出即点菜单：逐条 \`dsh plugin add\` 命令 + 一行合并命令，模型可直接执行或交给用户确认。

**值得学的点：** "把环境当数据"——插件的价值可以只是**编排其他插件**；零副作用的设计让纯逻辑部分极其好测（\`node test/recipe.test.mjs\`）。

## 4. dsh-gov：Agent 治理套件（企业级配套）

**解决什么问题：** 企业引入 DSH 的第一波问题永远是三个：谁能让 Agent 跑高危工具？出事了怎么追溯？钱花哪去了？

**三大支柱：**

| 支柱 | 机制 | 数据 |
| --- | --- | --- |
| 策略门禁 | 按工具/agent/工作区规则，allow / deny / ask；\`tool\` 支持 \`*\` 通配；\`priority\` 高者胜，平局 fail-closed（deny > ask > allow） | \`gov.json\` |
| 审计日志 | 每次工具调用（决定+结果）写入结构化 JSONL（\`audit.jsonl\`），可查询/导出/汇总 | \`audit.jsonl\` |
| token 配额 | 接宿主 \`tokenMeter\`，按 agent 累计用量，周期配额（day/week/month/total），超限注入上下文警告，可一键重置 | \`gov.json\` |

**接线方式（事件钩子）：**

- \`tools/pre-execute\`：门禁——命中规则返回 \`{ kind: "deny" | "ask" }\` 直接裁决，否则 \`next()\` 放行；
- \`tools/result\`：审计——记录 \`isError\` 结果；
- \`agent/pre-step\`：计量——\`ctx.tokenMeter.measure(agent.session)\` 取 \`totalTokens\`，超限时注入警告消息。

**设计要点（来自 README）：**

- **全局而非会话**：状态与日志持久化在 \`$DSH_HOME/gov/\`（默认 \`root\`），跨工作区一致；
- **fail-safe**：计量失败、持久化失败都**不阻塞 agent**（\`catch { return decision; }\` 式的兜底）；策略引擎平局默认 fail-closed；
- **审计不含参数内容**：只记工具名、agent、工作区、决定、理由、结果——刻意规避敏感信息落盘；
- **纯逻辑分层**：\`lib/policy.js\`（规则引擎）、\`lib/audit.js\`（审计模型）、\`lib/quota.js\`（配额计算）零依赖可单测；\`lib/index.js\` 只接线；
- 提示词段落教模型：被 deny 或配额警告**不要绕过**，去找用户调整。

**值得学的点：** 治理类插件 = 事件钩子 + 持久化 + 一个管理工具；"默认放行、规则收紧、平局 fail-closed"是平衡可用性与安全的成熟策略。

## 5. 三个插件共同的设计模式

| 模式 | focus | recipe | gov |
| --- | --- | --- | --- |
| 三件套结构（package.json + cordis.patch.yml + lib/index.js） | ✅ | ✅ | ✅ |
| 纯逻辑分离（零 DSH/Cordis 依赖的 lib/*.js + 单测） | \`board.js\` | \`recipe.js\` | \`policy/audit/quota.js\` |
| 动作收敛为 \`enum\` 的参数 schema | \`action\` 4 值 | \`action\` 4 值 | \`action\` 9 值 |
| 规范返回值 + \`render\` | ✅ | ✅ | ✅ |
| 文件安全（\`ctx.fs\` + containment） | ✅（工作区） | 无文件（只算） | ✅（\`$DSH_HOME/gov\`） |
| 生命周期管理（\`ctx.effect\` / \`ctx.on\`） | ✅ | ✅ | ✅（3 个钩子） |
| fail-safe（失败不拖垮 Agent） | ✅ | ✅（零副作用） | ✅（明确声明） |

**给新手的三个取经结论：**

1. **先分离纯逻辑**：把"解析/计算/渲染"写成不依赖 DSH 的函数，你就能在没有 DSH 的测试环境里把核心逻辑测到绿——三个插件全部如此；
2. **schema 先于实现**：把 \`parameters\`、\`output.schema\` 当接口契约先定死，实现只是填空；动作一律 \`enum\`，模型才调得准；
3. **安全是默认项**：能碰文件就做 containment 校验，能碰钱（token）就做配额与审计，能做失败兜底就 fail-safe——这三个插件把"不出事"设计成了默认行为。

## 6. 本章小结

\`focus\` 展示了"持久化 + 注入"的上下文工程，\`recipe\` 展示了"插件编排插件"的数据化思维，\`gov\` 展示了"钩子 + 持久化 + 管理工具"的治理结构。三者共同验证了本书前六章的每一条原则都可以落地。下一章 [08-常见问题](08-常见问题.md) 是踩坑速查表——Windows 路径、沙箱 EPERM、npm 403、git TLS……写插件路上会遇到的坑都在那里。
