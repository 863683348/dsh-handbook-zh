# 01 · 快速开始：30 分钟把 DeepSeek Harness 跑起来

> 一句话总结：DeepSeek Harness（DSH）是一个"用插件组合出来的 Agent 运行时"，你只需要安装一个 \`dsh\` 命令，就能启动 Web 界面、跑无头会话、管理插件——本章带你完成第一次完整的上手。

## 本章目标

读完本章并照做，你将：

- 安装并验证 \`dsh\` 命令；
- 启动一次 Web 会话（\`dsh web\`）并发出第一个任务；
- 用 \`headless\` 模式跑一个一次性的持久化会话；
- 记住 DSH 最常用的入口命令。

## 1. 准备工作

你需要一台能跑 Node.js 的电脑（Windows / macOS / Linux 均可）。DSH 本体是一个 npm 包，命令行工具叫 \`dsh\`，所以唯一硬性依赖是 Node.js 与 npm。建议使用当前 LTS 版本的 Node.js，具体版本要求以官方文档为准。

\`\`\`powershell
# PowerShell：查看 node 与 npm 版本
node --version
npm --version
\`\`\`

\`\`\`bash
# bash（macOS / Linux / WSL）
node --version
npm --version
\`\`\`

另外请准备好一个你常用的终端：Windows 上用 PowerShell 或 Windows Terminal，macOS/Linux 上用任意 shell。本书所有命令都给出双写法，绝大多数 \`dsh\` 命令在两个 shell 下完全一致，只有涉及路径、引号、环境变量时才需要区分。

## 2. 安装 dsh

\`dsh\` 是 DeepSeek Harness 中用于启动 profile 的命令，随 npm 包 \`@deepseek-ai/dsh\` 分发。全局安装它：

\`\`\`powershell
npm install -g @deepseek-ai/dsh
\`\`\`

\`\`\`bash
npm install -g @deepseek-ai/dsh
\`\`\`

安装完成后验证：

\`\`\`powershell
dsh --version
dsh --help
\`\`\`

\`\`\`bash
dsh --version
dsh --help
\`\`\`

- \`dsh --version\` 应打印版本号（本书写作时官方版本为 0.1.0-rc.6，以你安装到的版本为准）；
- \`dsh --help\` 打印启动器自己的帮助——注意它只包含启动器 flag，不包含某个具体应用（如 Web 应用）的 flag，这个区别在 [02-理解-profile](02-理解-profile.md) 里详细讲。

> Windows 提示：如果 \`dsh\` 提示"不是内部或外部命令"，多半是 npm 全局 bin 目录不在 PATH 里。执行 \`npm prefix -g\` 找到全局目录，把它的 bin 子目录加进 PATH 后重开终端。

需要升级时：

\`\`\`powershell
npm update -g @deepseek-ai/dsh
\`\`\`

\`\`\`bash
npm update -g @deepseek-ai/dsh
\`\`\`

## 3. 两个关键概念：$DSH_HOME 与 workspace

在跑第一条命令之前，先建立两个心智模型，它们贯穿全书：

- **$DSH_HOME**：DSH 的家目录，profile、全局配置、会话数据都存在这里。未设置时默认是用户主目录下的 \`.dsh\`（Windows 上即 \`%USERPROFILE%\\.dsh\`，例如 \`C:\\Users\\你\\.dsh\`）。查看它：

  \`\`\`powershell
  # PowerShell
  echo "$env:USERPROFILE\.dsh"
  \`\`\`

  \`\`\`bash
  # bash
  echo "$HOME/.dsh"
  \`\`\`

- **workspace**：Agent 干活的工作区。**运行 \`dsh\` 命令时所在的目录就是默认 workspace 根**。也就是说，你在哪个目录启动 DSH，Agent 默认就在哪个目录里读文件、写文件、跑命令。想让它处理某个项目，就先 \`cd\` 进那个项目再启动。

## 4. 第一次启动：dsh web

\`dsh web\` 是 \`--profile web\` 的别名，启动带图形界面的 Web 版 DSH。首次使用时，\`web\` profile 会**自动从随附模板初始化**，你不需要手动建目录。

\`\`\`powershell
# 在你想作为 workspace 的目录里启动（PowerShell）
cd D:\projects\my-first-dsh
dsh web
\`\`\`

\`\`\`bash
# bash
cd ~/projects/my-first-dsh
dsh web
\`\`\`

启动后终端会打印本地访问地址（通常形如 \`http://127.0.0.1:3000\` 或类似，**以终端实际输出为准**），用浏览器打开即可看到 Web 界面。在输入框里发第一个任务，比如：

> 帮我在当前工作区创建一个 README.md，说明这个目录的用途。

模型就会调用内置工具（读写文件、跑命令等）完成任务。Web 版适合交互式、看得见的过程。

Web 应用自己的 flag 要写在启动器 flag 之后——启动器只解析自己的 flag，其余内容全部交给 profile 应用：

\`\`\`powershell
dsh --profile web --port 8080
\`\`\`

\`\`\`bash
dsh --profile web --port 8080
\`\`\`

这里 \`--port 8080\` 属于 Web 应用而非启动器。同理，\`dsh --profile web --help\` 打印的是 Web 应用的帮助，而 \`dsh --help\` 才是启动器的帮助。

## 5. 第二次启动：headless 无头会话

不需要界面、只想要一个最终答案时，用 \`headless\` profile：

\`\`\`powershell
dsh --profile headless "写一段 200 字左右的 Python 代码，读取当前目录下所有 .md 文件的文件名并打印"
\`\`\`

\`\`\`bash
dsh --profile headless "写一段 200 字左右的 Python 代码，读取当前目录下所有 .md 文件的文件名并打印"
\`\`\`

\`dsh --profile headless "job"\` 会**运行一个全新的持久化会话**（persistent session），完成作业后**打印最终答案并退出**。它和 web 一样首次使用自动初始化。headless 适合脚本化、批量化、CI 里调用 DSH 的场景——你甚至可以把它当成一个"带 Agent 的 CLI"。

> 引号注意：PowerShell 与 bash 都要求把整个任务文本用引号包起来。如果任务文本里含有双引号，PowerShell 建议外层用单引号，bash 则注意转义，详见 [08-常见问题](08-常见问题.md)。

## 6. 常用入口命令速查表

| 命令 | 作用 | 说明 |
| --- | --- | --- |
| \`dsh --version\` / \`dsh --help\` | 版本 / 启动器帮助 | 启动器自己的 flag |
| \`dsh web\` | 启动 Web 版 | \`--profile web\` 的别名，首次自动初始化 |
| \`dsh --profile web --port 8080\` | 指定端口启动 Web 版 | \`--port\` 属于 Web 应用 |
| \`dsh --profile headless "任务"\` | 跑一次性无头会话 | 全新持久化会话，打印最终答案退出 |
| \`dsh --profile <name>\` | 启动任意 profile | 位于 \`$DSH_HOME/profiles/<name>\` |
| \`dsh plugin --profile <name> <pnpm args>\` | 管理该 profile 的插件 | 转发给 pnpm，如 \`add\` / \`remove\` |
| \`dsh --dump-config\` | 打印组合后的配置树 | 不启动，纯检查，见 02 章 |

## 7. 第一个完整任务示例

把前面的概念串起来，完整走一遍"建目录 → 启动 headless → 拿到产物"：

\`\`\`powershell
# PowerShell
mkdir D:\scratch\dsh-demo
cd D:\scratch\dsh-demo
dsh --profile headless "创建 hello.txt，内容为 'Hello from DeepSeek Harness'，然后读取并打印它"
Get-Content hello.txt
\`\`\`

\`\`\`bash
# bash
mkdir -p ~/scratch/dsh-demo
cd ~/scratch/dsh-demo
dsh --profile headless "创建 hello.txt，内容为 'Hello from DeepSeek Harness'，然后读取并打印它"
cat hello.txt
\`\`\`

预期结果：headless 会话在工作区（即 \`dsh-demo\` 目录）里创建了 \`hello.txt\`，打印其内容，然后退出；最后一行命令验证文件确实存在于当前目录。这就是 DSH 的最小闭环：**命令 → profile → Agent 工具 → workspace 产物**。

- [ ] \`dsh web\` 能启动并在浏览器打开界面
- [ ] \`dsh --profile headless "任务"\` 能打印答案并退出
- [ ] 理解"运行命令的目录 = 默认 workspace 根"
